# Deployment

Live: **https://braelaspin.dafeapp.com** (also http://68.183.91.240)

---

## ⚠️ This server runs live MT5 trading

`68.183.91.240` hosts a running MetaTrader stack. **Do not disturb it.**

| MT5 owns | Detail |
|---|---|
| Processes | Wine + 3 MetaTrader terminals, rpyc bridge |
| Ports | `127.0.0.1:18812-18814` (rpyc), `:5900`/`:5902` (x11vnc), `:22346` |
| systemd | **USER** units: `mt5-terminal*`, `xvfb*`, `fp10k-*`, `ftmo-*` |
| Memory | ~1.2 GB of 3.8 GB, plus ~500 MB swap |

Rules every change to this deployment must keep:

1. **Our units are SYSTEM-scoped; MT5's are USER-scoped.** Never run
   `systemctl --user` anything.
2. **Our ports (80/443/8080/5432/6379) avoid every MT5 port.**
3. **Postgres and Redis bind to `127.0.0.1` only.**
4. **`braelaspin.service` is capped at `MemoryMax=384M`, `CPUWeight=50`,
   `OOMScoreAdjust=500`** — if memory runs short the kernel kills the API, not
   a trade.
5. **No Docker.** Its iptables/FORWARD manipulation is unnecessary risk next to
   a live trading system, and the daemon costs ~100 MB this box cannot spare.
6. **Every deploy asserts MT5 is still running** and fails if it is not.

## Topology

```
                    ┌──────────────── 68.183.91.240 ────────────────┐
  Internet ──443──► │ Caddy                                          │
           ──80───► │   braelaspin.dafeapp.com  → TLS (Let's Encrypt)│
                    │   :80 (bare IP)           → plain HTTP         │
                    │     /            → /opt/braelaspin/web (static)│
                    │     /v1/*        ─┐                            │
                    │     /healthz      ├─► 127.0.0.1:8080 (Go API)  │
                    │     /webhooks/*  ─┘         │                  │
                    │                             ├─ postgres :5432  │
                    │                             └─ redis    :6379  │
                    │                                                │
                    │ MT5 (untouched): wine, rpyc :18812-14, x11vnc  │
                    └────────────────────────────────────────────────┘
```

**The web app and the API share one origin.** That is deliberate: production has
no cross-origin request at all, so CORS is only a local-dev concern.

Both hostnames serve the same site from one Caddy snippet, so they cannot drift.
The bare IP stays on plain HTTP because no public CA issues certificates for a
bare IP address.

## Deploy

### From your workstation — fastest loop, ~20 s

```bash
./deploy/deploy.sh                 # test, build, ship, restart, verify
./deploy/deploy.sh --web-only      # skip the Go build
./deploy/deploy.sh --api-only      # skip the web build
./deploy/deploy.sh --skip-tests    # emergency only
```

It refuses to continue if the tests fail. Deploying money code that has not
been tested is not a shortcut worth having.

### From GitHub — push to `main`

`.github/workflows/deploy.yml` runs on every push:

```
push to main
  ├─ test-api   go vet · unit + integration (real Postgres + Redis) · -race on the money path
  ├─ test-web   typecheck · core purity · unit tests · bundle size budget
  └─ deploy     build static binary + bundle → rsync → migrate → restart
                → smoke test from the public internet
                → assert MT5 is still running
```

Pull requests run the tests but never deploy. A failed health check after
restart **rolls back to the previous binary automatically**.

## One-time GitHub setup

Add three secrets at
`https://github.com/gibeongideon/braelaspin/settings/secrets/actions`:

| Secret | Value |
|---|---|
| `DEPLOY_HOST` | `trader@68.183.91.240` |
| `DEPLOY_KNOWN_HOSTS` | `68.183.91.240 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILdAJmezdq9/bZ9hnpg28b+Lsa88BqkWjX6m6HAynxbs` |
| `DEPLOY_SSH_KEY` | contents of `~/.ssh/braelaspin_deploy` (`cat ~/.ssh/braelaspin_deploy`) |

Then push:

```bash
git add .github deploy web DEPLOY.MD PLAN.MD TODO.MD
git commit -m "Add CI/CD, web client and staging deployment"
git push origin main
```

**About the deploy key.** It is a dedicated ed25519 key (`github-actions@braelaspin`)
installed alongside your existing key in `~/.ssh/authorized_keys` on the server,
so it can be revoked on its own without affecting your own access:

```bash
ssh trader@68.183.91.240 "sed -i '/github-actions@braelaspin/d' ~/.ssh/authorized_keys"
```

`DEPLOY_KNOWN_HOSTS` pins the server's host key. That is why the workflow does
not use `StrictHostKeyChecking=no`, which would accept any machine answering on
that address.

## Operations

```bash
# logs, live
ssh trader@68.183.91.240 "sudo journalctl -u braelaspin -f"

# status
ssh trader@68.183.91.240 "systemctl status braelaspin caddy postgresql redis-server --no-pager"

# rollback to the previous binary
ssh trader@68.183.91.240 '
  cd /opt/braelaspin
  cp "releases/$(ls -1t releases | head -1)" bin/braelaspin
  sudo systemctl restart braelaspin'

# confirm MT5 is healthy
ssh trader@68.183.91.240 '
  echo "terminals: $(pgrep -fc terminal64.exe)"
  systemctl --user list-units "mt5-*" "xvfb*" "fp10k-*" "ftmo-*" --no-pager'

# change config (then restart)
ssh trader@68.183.91.240 "nano /opt/braelaspin/.env && sudo systemctl restart braelaspin"
```

## Re-bootstrapping

`deploy/server-bootstrap.sh` is idempotent. It refuses to run if ports 80, 443
or 8080 are already taken, never touches an existing `.env`, and never touches
MT5. Safe to re-run after an OS upgrade.

## Known gaps

- [ ] **`APP_ENV=staging`, not `prod`.** Production mode additionally requires
      HTTPS, `sslmode=require` on the database, and `MPESA_CALLBACK_IP_ENFORCE=true`.
      Flip it when going live.
- [ ] **Postgres runs without TLS** (`sslmode=disable`) — acceptable only
      because it is on loopback.
- [ ] **No backups yet.** The ledger *is* the business: nightly `pg_dump -Fc`
      off-site plus WAL archiving, with a monthly restore drill that ends by
      running the invariant suite.
- [ ] **No monitoring or alerting.** At minimum, alert on
      `GET /v1/admin/integrity` going non-green.
- [ ] **M-Pesa credentials are placeholders.** Deposits and withdrawals cannot
      work until real Daraja credentials are in `/opt/braelaspin/.env`.
- [ ] **The bare IP is plain HTTP** — anyone using that URL sends their
      password in the clear. Prefer the domain; consider redirecting the IP to
      it once you are confident nothing depends on it.
